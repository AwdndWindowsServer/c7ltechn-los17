# 01 · 移植架构

## 1. 为什么选 mido 当 donor

| 维度 | C7 (c7ltechn) | 红米 Note 4 (mido) |
| --- | --- | --- |
| SoC | MSM8953 / SD625 | MSM8953 / SD625 |
| 分区习惯 | 无独立 vendor 分区（SYSTEM 3.52 GiB） | 无独立 vendor 分区 |
| Treble | 不支持 | 不支持 |
| Android 10 | 无官方包 | LineageOS 17.1 有稳定社区包 |

同 SoC + 同非 Treble 结构 → donor 的 init、HAL、firmware 加载路径几乎可以直接沿用，
唯一必须换掉的是**内核与 DTB**（C7 的面板/触摸/充电/传感器/音频都不在 mido 内格里）。

## 2. 流水线

```
donor zip ──20-unpack.sh──► donor-boot/ (kernel, ramdisk.cpio)
                       └──► system.img（或 system.new.dat[.br] 转 raw）
                       └──► vendor.img（mido 的包没有独立 vendor）

system.img ──30-assemble-system.sh──► 扩到 3.52 GiB-4MiB
                                     (+ vendor 合并 /system/vendor，/vendor 软链)
                                     (+ 可选 C7 blob 白名单覆盖)
                                     ► e2fsck / tune2fs

donor ramdisk ──40-make-bootimg.sh──► 去 fstab 的 verify/avb（重装系统无 AVB）
C7 4.9 Image.gz-dtb + msm8953-c7ltechn.dtb
                                     ► mkqcdt.py 生成 QCDT 表
                                     ► mkboot.py 打三星 v0 boot.img
                                     ► 断言 ≤ 32 MiB（C7 BOOT 分区）

──50-make-zip.sh──► TWRP zip（boot.img + system.img）/ Odin tar.md5
```

## 3. boot.img 的关键点（三星专有）

三星 aboot **不看**内核尾部的 appended dtb，而是读 boot header 里 `dt_size`（偏移 40）所指的
**QCDT 表**，用 `qcom,msm-id`/`qcom,board-id` 匹配当前机器的 board id，再把选中的 DTB 传给内核。
所以：

* dt 区必须放 QCDT v2 表：表项 24 字节 `(msm_id, board_id, subtype, 0, offset, size)`，magic `QCDT`；
* C7 用 `msm-id=293 (0x125)`、`board-id=8`、subtype `0/3/4`；
* 内核可以带 appended dtb，但真正生效的是 dt 区选出来的那个；
* 末尾必须追加 `SEANDROIDENFORCE`，否则部分 bootloader 拒绝启动。

`tools/mkboot.py` 与 `tools/mkqcdt.py` 就是照这个规则写的（AOSP 的 `bootimg.py` 不认三星 dt 区）。

## 4. 内核

基线 `zeelog/android_kernel_xiaomi_mido@lineage-22.2`（4.9.337 收尾），补丁 0001..0015：

* C7 板级 DTS `arch/arm64/boot/dts/qcom/msm8953-c7ltechn.dts`（含 `qcom,board-id = <8 4>`）
* `c7ltechn_defconfig`（= mido_defconfig + C7 驱动开关）
* Melfas MMS449 触摸、SM5705 充电、BHY 传感器中枢、RT5659 音频、S5K 相机、sec_class 等 shim

面板驱动不在补丁里，而是 `tools/panel-framework-setup.sh` 把三星 3.18 时代的面板框架
（`kernel/panel-3.18-source-bak2/`）搬进新内核，并以最小 hook 挂到 msm fbdev / DRM 上。
编译产物是 `Image.gz-dtb` + `qcom/msm8953-c7ltechn.dtb`。

> 注意：该脚本需要 `work/samsung-msm8953-3.18.tar.gz` 提供 `linux/self_display/*.h`、
> `linux/sec_debug*.h` 等三星私有头文件；缺了它会跳过并以警告继续，编译是否通过取决于用到的驱动。

## 5. 已知会被改写的分区

只写 `boot` 与 `system`（Odin 则只写 AP 槽里的这两个条目）。不碰 bootloader、EFS、persist、
param、modem、DSP、APNHLOS。
